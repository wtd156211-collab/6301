# 现场记录：分片键评估（摘录）

- 规模：主表三千二百万条，十六个分片；按均值算每个分片大约两百万条。
- 现状：最多的那个分片装了两千一百万条，另外几个分片空得能跑马；写入和查询都堵在热分片。
- 起因：当初选分片键的时候没人评估，随手挑了个字段；也没留下任何口径，事后想复算只能从头补。
- 观察一：这个字段的取值极不均匀，热度集中在少数几个值上，头部一个取值就能占到全表的六成以上。
- 观察二：一开始拿文件前几万行试算，看着相当均匀；后来才发现在线数据的热点整段都在文件尾部，
  只抽开头完全躲过了它。抽样口径不能只看前 N 行。
- 观察三：备选字段里，有的取值数比十六个分片还少；有的七成是空值；还有两个字段几乎一一对应，
  把它们拼成组合键也不会多出新的散列空间。
- 复现：`samples/data/` 里按同样形态抽小了几份数据，`samples/expected/` 是对应的期望结果。
- 待确认：抽样量、指标算法、倾斜阈值、建议规则都以 `README.md` 为准；这里只记现象。

本文件只记录现场情况，不构成评估口径。
